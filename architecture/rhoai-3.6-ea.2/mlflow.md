## Purpose

**Short**: MLflow is an RHOAI Python service and SDK for tracking experiments, serving artifacts and models, tracing GenAI applications, and brokering compatible gateway requests.

**Detailed**: The RHOAI image builds the MLflow Python packages and bundled React UI, then runs `python3.12 -m mlflow server` as UID 1001. The default server binds `0.0.0.0:5000`, enables Kubernetes-backed workspaces and artifact serving, and disables the assistant, AI gateway, telemetry, and job execution by environment defaults in the image.

The application combines Flask server routes with FastAPI gateway, assistant, artifact, job, MCP, and agent APIs, served through Uvicorn/Gunicorn-compatible entry points. It integrates with the Kubernetes API, relational databases and object stores through optional Python dependencies, and external model providers through configurable credentials. The analyzer identified 54 HTTP routes, no gRPC services, no CRDs, and one source-level Service identity; chart deployment details remain source-derived because templated Helm YAML was not parsed by the analyzer. ## Architectural Analysis

MLflow is packaged as a multi-purpose Python distribution but the RHOAI image uses it primarily as a long-running tracking and artifact server. A single container image contains the Python service, optional provider integrations, and the compiled UI. The entrypoint’s workspace flags make Kubernetes the control-plane boundary for workspace-aware operation, while the tracking backend and artifact repository are selected through MLflow configuration rather than embedded Kubernetes resources.

The HTTP surface is intentionally broad: standard MLflow tracking/model-registry routes coexist with artifact upload/download, OpenAI-compatible gateway routes, GenAI agent endpoints, job APIs, and MCP endpoint management. This makes deployment authentication and ingress policy important: source inspection found no authentication middleware in the FastAPI gateway, while the image itself only exposes port 5000 and declares no ingress or RBAC manifests in the analyzer’s deterministic inventory.

Builds use a UBI Python builder and a configurable `BASE_IMAGE`; wheels are installed with `--require-hashes`, but no RPM or artifact lock files were found in the checkout. The image includes `cryptography` and uses HTTPS-capable SDKs, yet application TLS minimum versions and cipher suites are not configured in the inspected source. These are explicit verification gaps rather than evidence of compliance or non-compliance.
