## Purpose

**Short**: Provides built-in, Hugging Face, and LLM-as-a-judge detector microservices for the FMS Guardrails Orchestrator.

**Detailed**: The repository packages detector implementations behind FastAPI/uvicorn HTTP services. The built-in image provides regex, file-type, and custom detector registries; the Hugging Face image loads a local model from a mounted model directory and returns content detections; and the LLM Judge image delegates evaluation to an OpenAI-compatible vLLM endpoint.

The Hugging Face and LLM Judge variants are modeled as KServe `InferenceService` workloads using non-multi-model `ServingRuntime` definitions. The Hugging Face example includes a MinIO-backed model store and a 100Gi PVC; the LLM Judge runtime instead uses `VLLM_BASE_URL` to reach an external or separately deployed predictor. All images run as an unprivileged UID 1001 in their Konflux form.

## Architectural Analysis

The component is a family of independently deployable Python services sharing a common FastAPI base class, request schemas, lifecycle management, error mapping, and Prometheus instrumentation. The built-in service is lightweight and stateless apart from in-process detector registries. The Hugging Face service is model-backed and resource intensive, with model initialization at process startup and explicit cleanup on shutdown. The LLM Judge service is a synchronous HTTP facade over an asynchronous client to a vLLM-compatible model endpoint.

KServe is the principal deployment integration. The supplied `ServingRuntime` objects use `multiModel: false`, expose port 8000, and select a detector-specific model format. The example InferenceServices request authentication and Istio injection through annotations, but the application itself registers no auth middleware. This makes platform ingress and KServe/Istio configuration the expected enforcement boundary; direct exposure of the containers would leave the APIs unauthenticated.

The release build path is more reproducible than the local Dockerfiles: the built-in Konflux image uses a digest-pinned AIPCC CPU image and hash-locked requirements, while the Hugging Face Konflux image receives CPU/CUDA base images through build arguments and installs the optional package set. No RPM lockfile, artifacts lockfile, or Hermeto prefetch metadata is present in this checkout, so OS and model artifacts remain outside the repository's hermetic lock contract.
