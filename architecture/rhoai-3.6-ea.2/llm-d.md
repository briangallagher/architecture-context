## Purpose

**Short**: llm-d is a Kubernetes-oriented distributed inference stack that combines vLLM-compatible model servers with an inference-aware router and accelerator-specific deployment recipes.

**Detailed**: llm-d supplies production recipes and images for high-scale LLM serving. Its architecture centers on a model-server pool, an Endpoint Picker (EPP), and a Gateway or standalone proxy. EPP performs inference-aware routing such as prefix-cache-aware, load-aware, latency-aware, and flow-control decisions rather than leaving balancing entirely to a generic service.

The checkout is primarily an integration and deployment repository: the main runtime images launch the vLLM OpenAI-compatible API, while Helm charts and kustomize components deploy model servers, routers, Gateway API resources, monitoring, autoscaling, and optional disaggregated prefill/decode or cache components. Hardware variants cover CPU, NVIDIA CUDA, AMD ROCm, Intel XPU, TPU, NPU, and RDMA-oriented tooling.

## Architectural Analysis

llm-d is a recipe-driven architecture rather than one monolithic controller binary. The runtime boundary is normally a vLLM model-server container on TCP 8000, fronted either by an EPP with an Envoy sidecar in standalone mode or by an existing Kubernetes Gateway in Gateway mode. `InferencePool` groups model-server endpoints for EPP selection, while request parsers and scheduling plugins are configured through `EndpointPickerConfig`.

The design separates inference policy from model execution. Model servers can be deployed as ordinary, prefill/decode-disaggregated, multi-host, or accelerator-specific workloads; router values and kustomize components select the corresponding image, topology, and sidecars. This supports portability across Gateway providers and accelerators, but also makes the effective deployment topology dependent on the selected guide and external charts/CRDs. Analyzer extraction confirms container entrypoints but did not verify a complete runtime deployment graph, service inventory, or HTTP endpoint inventory.
