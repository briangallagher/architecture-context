## Purpose

**Short**: OpenVINO Model Server (OVMS) serves optimized AI models through REST and gRPC APIs for KServe-compatible inference.

**Detailed**: OVMS is a C++ model-serving runtime that loads models from local or remote repositories and executes inference through OpenVINO. It supports KServe, TensorFlow Serving, and OpenAI-compatible generative interfaces, as well as model versioning, dynamic model updates, metrics, and accelerator-specific execution.

In RHOAI, the repository supplies both a cluster-scoped `ClusterServingRuntime` for KServe and a namespace-scoped `ServingRuntime` for the 2026.2 GPU runtime. The runtime starts `/ovms/bin/ovms`, exposes REST and gRPC inference surfaces, and is intended to run as a non-root container. Kubernetes/KServe supplies the model-serving workload and tenant namespace boundary; this repository does not contain an operator or controller.

## Architectural Analysis

The deployable artifact is a multi-stage UBI/PQC-based container containing the native OVMS binary, OpenVINO runtime libraries, optional Python support, and GPU-driver integration. The Konflux Dockerfile builds native dependencies and packages the result into `ubi-minimal-pqc`; the release image runs as UID 5000 with dropped application privileges. The same server binary is parameterized by gRPC and REST ports, model path, polling behavior, metrics, and optional API-key authentication.

The RHOAI integration is declarative rather than controller-driven. `kserve-openvino` is a cluster-wide runtime using REST port 8080 and gRPC port 9000, while `kserve-ovms-2026-2` is namespaced, GPU-oriented, and uses REST port 8888 and gRPC port 8001. Both use KServe v2 and gRPC-v2 protocol identities and readiness probes at `/v2/health/ready`. The repository also includes an optional NGINX mTLS wrapper for deployments that require certificate-based client authentication; the standard runtime manifests do not configure TLS or API-key values themselves.

Key risks are configuration-dependent security and supply-chain posture: OVMS disables authentication when no API key is supplied, the native runtime has no hard-coded TLS configuration, and the build installs several packages and source archives directly from network URLs without repository lock files. The code uses MD5 for local configuration-change detection, not password or token protection.
