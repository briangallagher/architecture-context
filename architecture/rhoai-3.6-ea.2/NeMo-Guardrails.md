## Purpose

**Short**: NeMo Guardrails is a programmable guardrail layer for LLM-based conversational applications.

**Detailed**: The component places configurable input, dialog, retrieval, execution, and output rails between an application and an LLM. It supports the OpenAI-compatible completion/chat-completion interaction model and can load local Colang/YAML configuration plus optional provider integrations.

The RHOAI image packages the server, its Python dependencies, and preloaded embedding/NLP model data. The Konflux entrypoint validates a selected configuration, starts the FastAPI server on a configurable port, and optionally wraps it with OpenTelemetry instrumentation.

## Architectural Analysis

This is primarily a library with an optional HTTP server, not a Kubernetes controller. The release checkout packages the server into one unprivileged container (UID 1001) and exposes port 8000. The container embeds model assets from four modelcar images and uses a local cache for Hugging Face, sentence-transformers, NLTK, and fastembed data.

The HTTP surface combines core guardrail operations (`/v1/checks`, `/v1/guardrail/checks`, completions, configuration and health) with an action server and optional model-backed helper services. The analyzer also observes benchmark/mock and helper-server routes, so those routes should not all be interpreted as the primary production listener. Authentication is not consistently established for the server routes by the available evidence; provider API credentials are read from runtime environment variables and outbound integrations are enabled by configuration.
