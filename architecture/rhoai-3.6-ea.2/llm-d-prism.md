## Purpose

**Short**: Prism is an interactive dashboard for discovering, validating, comparing, and publishing distributed-inference benchmark results.

**Detailed**: Prism combines a React 19/Vite single-page application with an Express server. The frontend visualizes benchmark, throughput, latency, quality, cost, prefix-cache, regression, and workload-catalog data; the server supplies runtime configuration and mediates access to cloud APIs and object storage.

The BFF proxies GIQ recommender requests to Google Kubernetes Engine Recommender, reads benchmark archives from Google Cloud Storage and AWS S3 through application services, and supports local benchmark files during development. The Results Store API writes and reads normalized benchmark bundles in a configured GCS bucket, while GitHub OAuth and GCS-hosted allowlists provide contributor and administrator authorization.

## Architectural Analysis

Prism is a monolithic web deployment with two logical planes: a browser-hosted React application and a server-side Express BFF. The BFF centralizes cloud credentials, bucket configuration, result processing, GitHub identity validation, rate limiting, and serving of the built SPA. In local development Vite runs on port 5173 and proxies `/api` to Express on port 3000; the production container runs the Express server on port 8080 and serves `dist` directly.

The principal data plane is object-storage based rather than Kubernetes-resource based. Catalog sources are treated as read-only inputs, while `RESULTS_STORE_BUCKET` is the writable destination for submissions and status transitions. Result metadata carries GitHub ownership and submission state, allowing application-level filtering for public, own, unlisted, and administrator-visible records. This makes authorization correctness and bucket IAM materially important because the component has no Kubernetes RBAC or namespace boundary.

The analyzer found no deployed Kubernetes workload or runtime API objects and reports partial coverage for dynamic JavaScript/TypeScript behavior. Therefore the concrete Express routes and storage flows below are supplemented by direct source inspection, while absence claims about dynamically composed routes or external clients remain bounded.
