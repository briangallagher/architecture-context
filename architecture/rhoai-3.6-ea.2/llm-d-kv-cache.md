## Purpose

**Short**: Provides KV-cache indexing and event processing for LLM serving, with in-memory, Redis/Valkey, and shared-storage connector implementations.

**Detailed**: The repository is primarily a Go library embedded in an inference-serving process. It consumes KV-cache events from vLLM or SGLang through ZeroMQ, tokenizes requests, maintains an index of blocks and serving pods, and returns pod scores used for prefix-cache-aware routing. The default in-memory index is complemented by Redis/Valkey for shared state and connector packages for filesystem, object-store, and PVC-backed offload.

It also contains runnable examples: an online HTTP scoring service, an IndexerService gRPC server/client, offline event processing, a pod reconciler that discovers serving pods, and a Valkey example. The repository's generic `deploy/` tree is a placeholder StatefulSet/kustomization; the `vllm-setup-helm/` chart is the more concrete deployment integration and wires vLLM to the KV-cache manager.

## Architectural Analysis

The core design separates event ingestion, token processing, indexing, and serving integration. A sharded worker pool preserves ordering by pod-derived keys while adapters decode engine-specific message formats. Index backends are replaceable: local LRU/Ristretto choices optimize latency, while Redis/Valkey provides shared state at the cost of a network hop. Pod discovery uses controller-runtime to watch ready, label-selected pods and creates a ZeroMQ subscriber per pod; a configured namespace narrows the watch, while an empty namespace permits cluster-wide discovery.

The online example exposes unauthenticated HTTP scoring handlers on port 8080 and the gRPC example listens on TCP 50051. These are examples rather than a complete production security boundary. The code explicitly uses insecure credentials for the local Unix-domain tokenizer and OTLP trace export, and the example HTTP server has no authentication middleware. Production deployment should provide network isolation and authenticated ingress where these endpoints are exposed.

The Helm chart enables a namespace-scoped vLLM Deployment, optional shared PVC, optional Redis, and a Secret containing a Hugging Face token. The generic kustomization references resources absent from this checkout, so its Service, Route, and RBAC behavior cannot be confirmed from rendered manifests.
