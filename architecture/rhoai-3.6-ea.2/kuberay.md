## Purpose

**Short**: KubeRay reconciles Ray workloads on Kubernetes, including clusters, jobs, scheduled jobs, and services.

**Detailed**: The operator watches namespace-scoped Ray custom resources and creates the Kubernetes pods, services, jobs, service accounts, roles, secrets, network policies, and routing objects needed to run them. RayCluster, RayJob, RayCronJob, and RayService controllers coordinate lifecycle and status, while a separate mTLS controller can provision per-cluster certificates through cert-manager.

The checkout also contains optional KubeRay API server, history server, collector, dashboard, submitter, and security-proxy artifacts. The RHOAI operator deployment is the primary analyzed deployment; its Gateway API authentication controller creates platform-namespace HTTPRoutes and uses the supplied kube-rbac-proxy image configuration. Static analyzer inventory reports 8 CRD/API rows, 1 operator Service, 18 RBAC roles, 21 controller watches, 32 HTTP endpoint registrations, and 5 gRPC services.

## Architectural Analysis

KubeRay is a controller-runtime control plane with namespace-scoped Ray APIs and a cluster-wide operator service account. Reconciliation is event-driven: Ray resources are the primary inputs, and owned Kubernetes resources provide secondary triggers. RayJob and RayService reuse RayCluster resources, while NetworkPolicy, authentication, and mTLS controllers add platform integration around the cluster lifecycle.

On OpenShift, the mutating RayCluster webhook forces secure-trusted-network behavior and disables user-requested direct ingress, directing access through Gateway API HTTPRoutes. The authentication path can create per-cluster service accounts, roles, role bindings, HTTPRoutes, ReferenceGrants, and proxy-backed services. This creates a strong platform integration point, but the operator retains broad cluster RBAC because it manages workloads across watched namespaces.

TLS behavior is profile-driven: the operator reads the OpenShift APIServer TLS profile and configures controller-runtime servers with TLS 1.2/intermediate defaults, TLS 1.3 for modern profiles, or the configured profile. The Konflux RHOAI image enables `CGO_ENABLED=1` and `GOEXPERIMENT=strictfipsruntime`; other repository images, including the experimental security proxy, use different build settings and should not be assumed to have the same compliance posture.

| Network traffic | Per-RayCluster NetworkPolicy; optional mTLS | Kubernetes/controller/cert-manager | Policy behavior is conditional on configuration and CNI support |

| Configuration & secrets | Namespace-scoped Secrets/ConfigMaps and generated TLS material | Kubernetes/controller | User-provided shared credentials may cross workload boundaries |
| API scoping | Namespace-scoped CRDs and namespaced watches/gets | Kubernetes/controller | ClusterRole permits broad list/watch where operator management requires it |
