## Purpose

**Short**: trainer-operator owns the RHOAI Trainer module and reconciles the platform-level `Trainer` resource into Kubeflow Trainer manifests, runtimes, image streams, RBAC, monitoring, and cleanup behavior.

**Detailed**: The operator watches the cluster-scoped `Trainer` API and dependent Kubernetes resources, checks JobSet and platform prerequisites, creates the target application namespace, renders the RHOAI overlay from embedded manifest templates, and applies resources through the ODH platform-utilities reconciliation framework. The CR is intentionally a singleton named `default-trainer`; its optional `spec.appNamespace` selects the namespace in which the namespaced Trainer control-plane resources are deployed, defaulting to `opendatahub`.

The container embeds three manifest trees (`/opt/manifests-template`, `/opt/runtimes-template`, and `/opt/imagestreams-template`). On OpenShift it additionally renders ImageStreams. The controller maintains release status, watches the platform configuration ConfigMap for version changes, performs status/availability checks, garbage-collects stale rendered resources, and removes legacy finalizers from upstream training resources during cleanup. The RHOAI overlay enables RHAI features and deploys the upstream Kubeflow Trainer CRDs, controller, admission webhooks, runtime definitions, and supporting roles.

## Architectural Analysis

trainer-operator is a cluster-scoped module operator with a namespace-scoped data-plane target. This split is central to its design: one platform-owned `Trainer` object controls a namespaced deployment, while several upstream Trainer resources (including `ClusterTrainingRuntime`) are cluster-scoped and cannot use a normal owner reference to the Trainer CR. The controller therefore uses label-aware garbage collection and explicit finalizer handling for those resources.

The reconciliation path is dependency-gated and declarative. It detects Kubernetes versus OpenShift, validates JobSet availability (and OpenShift JobSet operator health), renders the selected RHOAI Kustomize overlay, applies resources with a stable field owner and ordering, then reports deployment availability. The cache is narrowed to `APPLICATIONS_NAMESPACE` when injected by the platform operator and uses trainer labels for selected resource types; Namespace is deliberately uncached to avoid an accidental cluster-wide informer.

Metrics are intended to be HTTPS and protected by controller-runtime authentication/authorization, with a service-ca-issued certificate mounted from `trainer-operator-metrics-tls`. The repository’s default ServiceMonitor still sets `insecureSkipVerify: true`; a separate TLS patch provides certificate-backed verification but is commented out, so production overlays must enable the secure monitor configuration. Build-time FIPS signals are strong (`CGO_ENABLED=1`, `GOEXPERIMENT=strictfipsruntime`, and a UBI minimal-PQC runtime image), while application TLS policy is dynamically derived from the OpenShift API server TLS profile.

### Isolation Mechanisms

| Dimension | Mechanism | Enforced By | Gaps / Risks |
|-----------|-----------|-------------|--------------|
| Auth & AuthZ | Kubernetes RBAC with separate Trainer admin/viewer roles and a manager ClusterRole | Kubernetes | Manager has broad cluster-level permissions because it creates cluster-scoped upstream resources; create/list/watch grants are intentionally not resource-name bounded. |
| Data storage | No database or persistent data store; training resources are namespace-scoped where defined | Kubernetes / upstream Trainer | ClusterTrainingRuntime definitions are shared cluster resources; tenant-specific isolation is delegated to upstream Trainer and Kubernetes RBAC. |
| Network traffic | Metrics NetworkPolicy permits same-namespace and named monitoring namespaces | Kubernetes NetworkPolicy | Policy covers operator metrics ingress only; no inter-tenant training data-plane policy is authored here. |
| Compute & resources | `LimitRange` is read and embedded manifests carry workload resource settings | Kubernetes / upstream manifests | Operator does not define per-tenant quotas or node isolation. |
| Configuration & secrets | Target namespace and generated TLS/config resources are namespace-scoped; service-ca provides metrics cert | Kubernetes / platform operators | Shared cluster-level Trainer/RBAC/runtime resources require correct platform RBAC. |
| API scoping | Cache can be bounded by `APPLICATIONS_NAMESPACE`; rendered namespaced resources use resolved namespace; cluster-wide cleanup lists upstream runtime resources | Kubernetes / controller | Standalone mode leaves the cache unbounded, and explicit cluster-wide cleanup is a privileged operation. |
