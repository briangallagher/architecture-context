**Short**: A Kubernetes operator that declaratively deploys and manages MLflow instances, their supporting workloads, storage, networking, RBAC, and migrations.

**Detailed**: The operator watches MLflow custom resources and renders the vendored `charts/mlflow` Helm chart into namespaced workloads. It manages deployments, services, service accounts, PVCs, secrets, jobs, CronJobs, NetworkPolicies, monitoring resources, and optional Gateway API HTTPRoutes. It also reconciles the cluster-scoped `MLflowOperator` configuration and can reconcile namespace RBAC when enabled.

The operator supports OpenDataHub and RHOAI deployment modes. Its target operand namespace is resolved at startup and used for cache, reconciliation, and namespace-scoped RBAC. The RHOAI overlay enables namespace RBAC and mounts a certificate for authenticated HTTPS metrics. MLflow status exposes an in-cluster service address and, when configured, gateway-derived URLs.

## Architectural Analysis

This is a controller-runtime operator with a deliberately split security boundary: cluster-scoped reconciliation and RBAC setup are combined with namespace-scoped operand management. The target namespace is resolved before manager construction, and cache selectors are used to reduce the watched resource set and keep named-resource RBAC compatible.

Ingress is capability-detected rather than assumed. When Gateway API is present, the operator watches and creates HTTPRoutes; when it is absent, ordinary MLflow reconciliation can continue, but artifact-server mode reports an explicit prerequisite failure. The operator relies on the platform Gateway for the ingress data plane and does not deploy the RHOAI ingress stack itself.

The Konflux production build has explicit strict FIPS runtime settings and CGO enabled. The repository nevertheless contains a non-AIPCC Python test image and lacks OS/artifact lockfiles, so supply-chain hardening is stronger for the production Go dependency graph than for all images and build inputs.
