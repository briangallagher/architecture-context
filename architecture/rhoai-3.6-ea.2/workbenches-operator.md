## Purpose

**Short**: Reconciles the cluster-scoped `Workbenches` resource and deploys the RHOAI notebook-controller and notebook-manifest stack.

**Detailed**: The operator is a controller-runtime manager for the platform Workbenches module. A platform orchestrator creates the singleton `default-workbenches` custom resource and projects platform, gateway, and MLflow state into its spec. The reconciler validates management state, resolves the applications namespace, renders the committed operand manifests, applies them with server-side apply, and reports release and readiness status.

When managed, it deploys the Kubeflow notebook controller, ODH notebook controller, and platform notebook ImageStreams/manifests. It adds a cleanup finalizer, owns operand resources, watches operand Deployment availability, and removes managed resources when the module is removed. Two fail-closed mutating webhooks enrich Kubeflow Notebook objects with connection secrets and hardware-profile scheduling/resource settings.

## Architectural Analysis

This is a cluster-scoped module operator with namespace-scoped operand deployment. The `Workbenches` CR is intentionally restricted to the name `default-workbenches`; tenant/workload isolation is consequently delegated to the namespace and RBAC model of the deployed notebook stack. The operator has broad cluster permissions because it creates CRDs, webhook configurations, namespaces, operand RBAC, NetworkPolicies, ImageStreams, and workloads, but its separate `bind`/`escalate` role is constrained to named upstream ClusterRoles.

The release branch is designed for hermetic builds: `opt/manifests/` is committed into the image and copied to a temporary working tree before Kustomize rendering. `Dockerfile.konflux` is the preferred build definition and uses CGO plus `strictfipsruntime`, a UBI Go builder, and a UBI minimal PQC runtime image. Runtime TLS is profile-driven on OpenShift and uses a hardened TLS 1.2-plus fallback elsewhere; webhook certificates are provisioned by OpenShift service-ca or cert-manager based on API discovery.

The analyzer found no component-owned Gateway API routes or serving-runtime definitions. Gateway URL is a rendered operand parameter, so external notebook ingress is supplied by the deployed notebook manifests/platform rather than by this manager Deployment. Analyzer coverage remains partial for dynamic HTTP/service construction, authentication accounting, and some runtime integration relationships; those limitations are retained below as unknowns rather than inferred facts.
