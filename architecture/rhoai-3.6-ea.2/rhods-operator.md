## Purpose

**Short**: The RHOAI platform operator configures the Data Science Cluster, installs and coordinates optional AI/ML component operators, and manages platform authentication and ingress.

**Detailed**: `rhods-operator` is a controller-runtime operator whose primary manager watches cluster-scoped platform configuration and component resources. It reconciles `DSCInitialization`, `DataScienceCluster`, `GatewayConfig`, `Auth`, component CRs, and module dependencies, applying manifests and maintaining component status. The release contains the main manager and a cloud-manager executable, with manifest tooling and supporting Go command entry points.

The operator also owns the RHOAI 3.x ingress plane. It creates a Gateway API entry point, Envoy authentication filters, an OIDC/OpenShift OAuth authentication proxy, TLS policy, network policy, and callback routes. On OpenShift it can additionally create an OCP Route and nginx-backed redirects for legacy dashboard and gateway hostnames.

## Architectural Analysis

The operator is a cluster-level orchestration control plane rather than a tenant-facing application. A dependency DAG and runlevels coordinate independently enabled components such as Data Science Pipelines, Ray, Kueue, and TrustyAI, while additional modules include KServe, model registry, workbenches, trainer, Feast, monitoring, MLflow, MCP lifecycle, AI gateway, and Spark. Component reconciliation creates deployments, RBAC, monitoring resources, network policies, and supporting configuration from embedded or prefetched manifests.

Gateway reconciliation is conditional on `GatewayConfig` and detected platform capabilities. The preferred RHOAI 3.x path is Gateway API plus Envoy and an auth proxy; `OcpRoute` remains an explicit/compatibility mode. Legacy redirect resources are created only when the Dashboard exists and redirects are enabled, and are skipped on XKS where OpenShift Routes are unavailable. This makes the ingress surface intentionally dynamic and platform-dependent.

The manager reads cluster TLS policy and converts it to Go and auth-proxy settings. Fallback behavior floors unsupported or unavailable profiles to TLS 1.2 with an intermediate cipher set. The Konflux manager build enables CGO and `strictfipsruntime`; the analyzed branch contains `go.sum`, but no RPM/artifact lock files were found in the checkout, so OS and prefetched-manifest reproducibility remain pipeline concerns.
