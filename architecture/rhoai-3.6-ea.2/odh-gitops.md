## Purpose

**Short**: Provides repeatable Kustomize and Helm-based installation and configuration of OpenDataHub/RHOAI platform dependencies.

**Detailed**: `odh-gitops` is an administrator-owned declarative source of truth for platform dependency installation. Its Kustomize tree composes OLM operator subscriptions and then applies configuration resources for Kueue, JobSet, Leader Worker Set, and Red Hat Connectivity Link. The repository is intended for GitOps tools such as Argo CD and Flux, or direct `kubectl apply -k` use.

The repository also ships OpenShift and external-Kubernetes Helm charts. The OpenShift chart configures ODH/RHOAI operator installation, platform component management states, gateways, and post-install custom resources. The XKS chart bundles dependency charts and direct operator workloads for AWS, Azure, and CoreWeave environments where OLM is unavailable. No application runtime or container image is built by this repository.

## Architectural Analysis

This is a declarative orchestration artifact rather than a runtime service. The root Kustomization composes `dependencies/` and `configurations/`; dependency components install operators through OLM, while the configuration layer is applied after their CRDs and controllers exist. The README explicitly calls for Argo CD `SkipDryRunOnMissingResource=true` because those stages are not simultaneously available during the first sync.

The two Helm charts encode the installation-model split: OLM subscriptions are the default on OpenShift, while the XKS chart embeds operator charts and hook jobs for non-OLM clusters. Profiles and values control management states and optional dependencies. This makes the repository a platform topology control plane, but also means the security, availability, and runtime API properties of the deployed operators remain delegated to their respective component releases.
