## Purpose

**Short**: CodeFlare SDK is a Python client for creating and managing Ray batch-compute resources through Kubernetes and Kueue.

**Detailed**: The SDK gives notebooks and Python applications a high-level interface for requesting compute, creating and observing RayCluster resources, submitting Ray jobs, and managing cluster lifecycle. It uses the Kubernetes Python client and KubeRay/Ray APIs rather than running a persistent control-plane service of its own.

The repository also contains an end-to-end test image and a test-only MinIO deployment used by integration tests. Those assets exercise the SDK against OpenShift/Kubernetes, Ray, Kueue, and S3-compatible storage; they are not the SDK's production runtime topology.

## Architectural Analysis

CodeFlare SDK is primarily a client-side library. `Cluster` and `RayJob` code serialize and submit Ray custom resources through the Kubernetes API, use Kueue queue information when configured, and connect to Ray's job-submission interface after a cluster becomes available. Namespace and queue values are supplied by the consumer, so tenancy and resource authorization are delegated largely to Kubernetes RBAC, Kueue, and the Ray operator.

Authentication has a modern `kube-authkit` path with auto-detection, kubeconfig, in-cluster, OIDC, and OpenShift/token workflows, while deprecated compatibility classes remain. The SDK can retrieve a Ray CA secret and generate short-lived client certificates for mTLS. The main architectural risk is that the legacy token path exposes a `skip_tls` option that disables certificate verification; callers must avoid that option in production.

The only container build is `images/tests/Dockerfile`, a Debian Python test image with Poetry, `oc`, Chrome, and test dependencies. It is not a Konflux Dockerfile and does not define a production SDK server. The checked-in MinIO deployment is single-replica, uses a PVC and a Secret, and is intended for end-to-end testing.
