## Purpose

**Short**: KServe is the Kubernetes control plane and serving-runtime library used to deploy and expose machine-learning inference workloads, including AutoGluon runtimes.

**Detailed**: The repository combines the KServe controller manager with specialized controllers for `LLMInferenceService`, local-model caching, and local-model nodes. Controllers reconcile inference-related custom resources into Kubernetes Deployments, Services, Jobs, PVCs, ConfigMaps, Secrets, HPAs, Gateway API resources, and serving-runtime configuration.

It also contains Python model-server implementations and protocol definitions. The AutoGluon container is one of several Python serving variants; the broader repository supplies the common REST/gRPC inference contracts, storage initialization, model loading, routing, webhooks, and Kubernetes API integration needed by platform deployments.

## Architectural Analysis

KServe is a broad control-plane repository rather than a single AutoGluon-only service. The principal architectural boundary is between cluster-scoped reconciliation/webhook control and namespace-scoped inference workloads. This permits a shared operator to manage many tenants while leaving end-user authentication, gateway policy, resource quotas, and network isolation to the platform installation.

The release branch has a substantial manifest surface: multiple controller variants, full/minimal CRDs, LLM Gateway API resources, local-model agents, cert-manager integration, and framework-specific Python images. The analyzer provides strong deterministic inventory for CRDs, manifests, dependencies, and entrypoints, but marks dynamic HTTP routes, gRPC registration, Kustomize patches, authentication, and webhook semantics as partial. Those limits are important for operational decisions: runtime ports, route hosts, final auth policy, and exact watch predicates should be confirmed from the rendered deployment.

The main supply-chain observation is that the Konflux AutoGluon image installs Python content without an AIPCC base image or AIPCC package-index/tooling evidence. Overlay 0017 identifies AIPCC as the required secure-build ecosystem for accelerator-aware RHOAI Python containers, so this image is a migration candidate even though the repository does not prove that it currently ships accelerator-specific packages.
