## Purpose

**Short**: Maintains digest-pinned RHOAI container image references that must be available for disconnected mirroring even when they are not referenced directly by platform manifests.

**Detailed**: This repository is a source-data catalog rather than a deployable service. Its `rhoai-disconnected-images.yaml` file enumerates additional images for RHOAI workbenches, pipeline runtimes, Ray, FMS HF tuning, and training runtimes. Image references use immutable SHA-256 digests, while comments associate entries with release lines, accelerator variants, or tracking issues.

The catalog includes current/additional images as well as explicitly labelled N-1 and deprecated groups. A release or mirroring process can consume the list to pre-stage images in disconnected registries; this checkout itself creates no Kubernetes workload, API, service, or network endpoint.

## Architectural Analysis

The component is a release and supply-chain input for disconnected RHOAI installations. Its architecture is intentionally declarative: a single YAML list maps image identities to immutable digests, and comments provide human-readable tag/version context that is not encoded in the digest reference itself.

The catalog spans multiple accelerator families (CPU, CUDA, and ROCm) and several RHOAI-era image sets. Because deprecated and N-1 images remain represented, consumers must apply release-policy filtering rather than treating every entry as an active runtime. The repository has no lockfile, image-signature policy, or deployment manifest, so digest pinning provides reproducibility of referenced content but does not by itself establish provenance, vulnerability status, or FIPS compliance.
