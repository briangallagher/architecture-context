## Purpose

**Short**: Provides NIXL/UCX GPU data-transfer benchmarks, preflight diagnostics, and network-performance test tooling for llm-d inference pods.

**Detailed**: The repository is an operational utility, not a controller or long-running application. It builds a CUDA-based image containing GPU, RDMA, UCX, GDRCopy, NIXL, and Python benchmark dependencies. The benchmark creates tensor datasets, exchanges NIXL agent metadata over a ZeroMQ TCP socket, and measures GPU/CPU data transfers between a creator and peer.

The repository also contains raw Kubernetes Pod manifests for client/server test participants, with an optional RoCE/multi-NIC variant. A helper script applies those manifests and runs `ucx_perftest` or the Python NIXL benchmark. Separate skills provide preflight inspection and network/GPU topology tests for existing llm-d pods.

## Architectural Analysis

This component is a test-plane companion to llm-d rather than a platform-managed workload. Its Kubernetes resources are intentionally minimal raw Pods plus one NodePort Service; there is no Deployment controller, reconciliation loop, CRD, operator RBAC, or kustomize composition. The server Pod is kept alive with `sleep infinity`, and the actual UCX or Python listener is started interactively by `benchmarks/benchmark_deployment.sh`.

The normal path uses TCP transport, while the `_roce` manifests add a Multus network attachment, `IPC_LOCK`, shared memory, and `roce_gdr` resources for RDMA/GDR testing. The design is performance-oriented and assumes a trusted test namespace: the NodePort has no application authentication or TLS, images use mutable `latest` tags, and the Docker build downloads several external archives without repository lock files or digest pinning. These properties are appropriate risks to isolate when the utility is used outside a controlled benchmark environment.
