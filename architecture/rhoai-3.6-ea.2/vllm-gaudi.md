## Purpose

**Short**: Provides Intel Gaudi HPU support for vLLM and packages it in a RHEL 9 container that runs the vLLM OpenAI-compatible inference server.

**Detailed**: `vllm_gaudi` is an out-of-tree vLLM platform plugin for Intel Gaudi accelerators. It supplies HPU platform selection, attention and fused operations, model integrations, scheduling, sampling, distributed communication, and KV-cache transfer implementations while using vLLM as the serving framework.

The Konflux Gaudi image builds a UBI 9.6 runtime, installs Habana Synapse and PyTorch components, builds vLLM and this plugin from configured commits, and starts `vllm.entrypoints.openai.api_server`. The repository itself contains no Kubernetes manifests; deployment topology, service exposure, probes, and endpoint authentication are therefore supplied by the consuming RHOAI serving stack and are not established here.

## Architectural Analysis

The component is an accelerator-specific extension layer rather than an independent control plane. At runtime, vLLM owns request handling and model serving, while `vllm_gaudi` is loaded through vLLM’s platform/plugin interfaces to select HPU execution and replace or augment execution paths. The package spans device initialization, HPU attention and operators, multimodal/model adapters, asynchronous scheduling, speculative decoding, and NIXL-based KV-cache movement.

The preferred release image is a three-stage build: UBI system and Habana runtime setup, Habana PyTorch installation, then vLLM plus the pinned Gaudi plugin. The image uses `Dockerfile.konflux.gaudi`, runs unprivileged as UID 2000, and embeds source clones of both vLLM and vLLM-Gaudi. The build is not based on an AIPCC image and removes `openssl-fips-provider-so`; this is a material supply-chain and FIPS-compliance risk for a RHOAI product image.
