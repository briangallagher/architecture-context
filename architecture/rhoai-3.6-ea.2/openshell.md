## Purpose

**Short**: OpenShell provides a policy-enforced runtime for autonomous AI agents by managing isolated sandboxes, credentials, identity, and network egress.

**Detailed**: The gateway is the authenticated control plane. It exposes the OpenShell API, persists gateway state, manages sandbox lifecycle through pluggable compute drivers, stores or resolves provider credentials through pluggable credential drivers, and maintains supervisor sessions and relays. The CLI, TUI, Rust SDK, Python package, and Go SDK are user-facing or integration clients.

Every sandbox contains a supervisor that launches the agent as a restricted child process. The supervisor applies filesystem and process restrictions, runs the network policy proxy, injects authorized provider credentials at runtime, emits security/telemetry events, and maintains an outbound authenticated session to the gateway. Compute integrations cover Docker, Podman, Kubernetes, MicroVM, and Windows MXC; credential integrations include encrypted database storage, Kubernetes Secrets, Vault, and local drivers.

## Architectural Analysis

OpenShell separates control-plane semantics from infrastructure-specific drivers. The gateway owns sandbox, policy, provider, workspace, session, and authorization state, while drivers translate lifecycle and credential contracts to Docker, Podman, Kubernetes, VM, or external secret-store operations. The supervisor is the consistent data-plane enforcement point across those runtimes.

The server multiplexes gRPC and HTTP on the gateway listener, with separate optional health and metrics listeners. Gateway APIs are defined in Protocol Buffers and include sandbox, provider, policy, workspace, relay, and supervisor-session operations. Kubernetes deployment is not an operator in this repository: the Helm workspace chart supplies a service account, Role, RoleBinding, and NetworkPolicy for a gateway that interacts with externally owned Sandbox resources.

The security model is defense in depth: TLS/mTLS or OIDC authenticates control-plane traffic; short-lived Ed25519 JWTs authenticate sandbox supervisors; policies constrain filesystem, process, network, and provider access; and provider credentials are marked secret in the protocol and delivered as runtime environment data rather than written to sandbox filesystems. The release build uses Rustls with AWS-LC crypto features and digest-pinned UBI9 images, but the CLI is intentionally statically linked, so FIPS certification should be established from the complete downstream image and check-payload evidence rather than inferred from the presence of UBI.
