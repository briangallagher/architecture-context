## Purpose

**Short**: Reconciles the platform-level `FeastOperator` resource and deploys the Feast operator module and its feature-store dependencies.

**Detailed**: The module is installed and configured by the OpenDataHub Operator through the modular handler framework. It accepts one cluster-scoped `FeastOperator` resource, validates optional external OIDC configuration, renders bundled kustomize manifests, and applies the resulting Feast operator resources to the configured applications namespace.

The reconciler manages deployment, upgrade and release-status actions, observes the deployed resources, and reports conditions on the `FeastOperator` status. It also performs selector migration for an existing Feast controller Deployment and explicitly cleans up component-labeled cluster-scoped RBAC resources that cannot be garbage-collected through owner references.

## Architectural Analysis

This is a control-plane-only module operator. The binary has a Cobra entrypoint with `operator` and `chartgen` subcommands; the deployed operator command starts a controller-runtime manager with health/readiness probes, leader-election support, and a namespace-scoped cache for namespaced application resources. Manifests are packaged into the image and copied by an init container into an `emptyDir` before the manager renders them.

The central API is intentionally a cluster-scoped singleton: the CRD requires the name `default-feastoperator` and carries platform-wide OIDC settings rather than tenant-specific configuration. The reconciler applies the generated Feast operator stack in one applications namespace, while its cluster-wide service account can manage Feast, notebooks, MLflow, RBAC, monitoring, and related OpenShift resources. This makes Kubernetes RBAC and namespace selection the primary isolation boundary; the module itself does not implement user or tenant authorization.

The release overlay pins the Feast controller and feature-server images by tag and the RHOAI cron-job image by digest. The operator image itself is built from digest-pinned UBI images with `CGO_ENABLED=1` and `GOEXPERIMENT=strictfipsruntime`, but the repository contains no RPM, artifact, or Hermeto lock metadata, so complete supply-chain hermeticity is not established here.
