## Purpose

**Short**: TrustyAI Service is a FastAPI service for inference-data ingestion, responsible-AI metrics, explainability, and Prometheus publication.

**Detailed**: The service consumes KServe v2 inference payloads and CloudEvents, persists inference data using either PVC-backed HDF5 files or MariaDB, and exposes APIs for drift and fairness calculations, metadata, data upload, and explainers. A background scheduler computes configured metrics and publishes them through Prometheus-compatible metrics.

It is packaged as an unprivileged Python container and served by Hypercorn. The main API uses loopback HTTP for kube-rbac-proxy and can optionally expose direct HTTPS; a separate listener serves health probes and KServe consumer endpoints.

## Architectural Analysis

The service is a single Python process with two ASGI applications. The primary FastAPI application registers core ingestion, data, metadata, metrics, and feature-flagged fairness, drift, and explainer routers. The health application is deliberately smaller and exposes probes plus the KServe consumer callbacks on port 8080. A lifespan task periodically calculates metrics and is cancelled during shutdown.

Storage is selected by `SERVICE_STORAGE_FORMAT`, defaulting to PVC/HDF5 and optionally using MariaDB with environment-based connection configuration. The MariaDB implementation includes schema management and migration paths from PVC and legacy database data. Dataset names are validated before HDF5 path construction, and MariaDB table names are generated rather than taken directly from model input.

Authentication is not implemented in the FastAPI application. The deployment contract expects kube-rbac-proxy to front the loopback HTTP listener; direct HTTPS and the health listener are application-level binds, so deployment manifests must provide the intended network exposure and protection. Wildcard CORS with credentials is enabled in the main app and should be reviewed alongside that external enforcement boundary.
