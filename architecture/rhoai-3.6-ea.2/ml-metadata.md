## Purpose

**Short**: ML Metadata (MLMD) stores and serves metadata about machine-learning artifacts, executions, contexts, types, events, and lineage through a gRPC API.

**Detailed**: The repository provides the MLMD library, generated Python bindings, C++ metadata-store implementation, database adapters, and a standalone `metadata_store_server` binary. The server initializes a metadata store, optionally performs schema migration, and exposes `MetadataStoreService` on gRPC port 8080 by default.

The service supports in-memory/fake storage for development and SQLite, MySQL, and PostgreSQL backends for persistent deployments. The RHOAI Konflux image builds the server with Bazel and C++17, runs it as UID/GID 65534, and passes the port and server configuration file through container environment variables.

## Architectural Analysis

MLMD is a stateful application service with a narrow network surface and a broad typed RPC contract. `metadata_store_server` creates the configured database adapter before registering `MetadataStoreService`; write APIs maintain typed metadata and lineage relationships, while read APIs retrieve nodes and traverse context and lineage relationships. The database abstraction allows the same service contract to run against SQLite, MySQL, PostgreSQL, or an ephemeral fake store.

The release image is a multi-stage UBI build. The builder compiles the server and packages the extracted MariaDB client source, while the `ubi-minimal-pqc` runtime supplies a reduced RHEL runtime and timezone data. The service binds to `0.0.0.0`, defaults to insecure gRPC unless an SSL configuration is present, and has no repository-local Kubernetes manifests, service objects, RBAC, or ingress definitions. Deployment topology, authentication policy, and production network protection therefore remain platform/deployment concerns and are not established by this checkout or the analyzer baseline.
