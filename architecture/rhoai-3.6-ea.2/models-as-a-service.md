## Purpose

**Short**: Provides a multi-tenant model catalog, subscription and API-key management, and controller-managed model-serving routes for RHOAI.

**Detailed**: models-as-a-service combines a Go HTTP API with a controller-runtime manager. The API exposes model and subscription discovery plus API-key lifecycle operations, while the manager reconciles tenant, model reference, external model, authorization policy, subscription, and deployment resources. The controller also creates or updates Gateway API HTTPRoutes and policy resources used to expose model inference safely.

The component uses namespace-scoped MaaS resources to represent tenant-owned configuration and uses Kubernetes authorization checks together with gateway-level Authorino/Kuadrant policies. API-key metadata is stored in PostgreSQL; model-serving state is discovered through Kubernetes and KServe resources. Deployment manifests support OpenShift and xKS variants, optional infrastructure namespace separation, secure service endpoints, observability, and payload processing.

## Architectural Analysis

The system separates control-plane reconciliation from request handling. `maas-controller` owns the lifecycle of tenant and subscription-related Kubernetes resources and can deploy the API, payload-processing components, policies, and per-route limits. `maas-api` is a relatively thin HTTP façade: it reads namespace-scoped CRs, checks user identity and authorization through Kubernetes APIs, selects subscriptions, and persists API-key metadata in PostgreSQL. This allows the API to remain stateless apart from the database and Kubernetes caches.

Ingress is designed around the RHOAI 3.x Gateway API. The API is internal as a ClusterIP service and is reached through an HTTPRoute attached to `maas-default-gateway`; Authorino evaluates API keys, Kubernetes TokenReview identities, and optional OIDC JWTs before forwarding identity and subscription headers. Per-subscription policies and a gateway default-deny TokenRateLimitPolicy provide layered authorization and rate limiting. Secure overlays encrypt API and metrics traffic, but the Istio DestinationRule currently sets `insecureSkipVerify: true` because the managed gateway cannot yet receive the service CA bundle; this is an explicit certificate-validation gap.

The repository contains both static composition and runtime-installed platform dependencies. Kustomize overlays select OpenShift versus xKS resources, while the controller receives related image references and namespace settings through `maas-parameters`. The analyzer baseline identified 8 CRDs, 1 workload, 2 services, 2 roles, 1 HTTPRoute, 35 controller watches, 18 registered API routes, and no gRPC services.
