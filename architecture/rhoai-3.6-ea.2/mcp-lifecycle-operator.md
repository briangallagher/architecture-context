## Purpose

**Short**: Kubernetes operator that declaratively deploys and manages MCP servers, including their Deployments, Services, NetworkPolicies, configuration refreshes, and MCP protocol readiness verification.

**Detailed**: The operator reconciles `mcp.x-k8s.io/v1alpha1` `MCPServer` resources. For each namespaced resource it creates or updates a workload from the requested container image, a ClusterIP Service on the configured MCP port, and an ingress-only NetworkPolicy. Owner references allow Kubernetes garbage collection to remove managed resources with the parent CR.

After the workload is available, the controller performs an MCP initialize handshake using the upstream MCP Go SDK and records server identity, protocol version, and capabilities in status. ConfigMap and Secret references are indexed and watched so changes trigger reconciliation; a configuration hash drives managed workload rollouts. Optional per-server TLS settings and operator-level TLS profiles support secure MCP endpoint verification.

## Architectural Analysis

This is a conventional controller-runtime operator with one primary reconciliation loop. The `MCPServer` CR is the source of truth, while Deployments, Services, and NetworkPolicies are derived resources owned by that CR. Validation precedes resource reconciliation, and status conditions distinguish accepted configuration, deployment availability, network-policy availability, and MCP endpoint verification.

The operator adds an application-level readiness gate beyond Kubernetes Deployment readiness: it connects to the advertised MCP URL and verifies the protocol handshake. Handshake failures are retried with bounded exponential backoff; HTTP 401/403 responses are treated as reachable endpoints because authentication may be intentionally external to the operator. This makes protocol validation useful without requiring the controller to possess every server credential.

Security posture is split between Kubernetes controls and configurable transport behavior. The manager runs non-root with a read-only root filesystem and dropped capabilities. Metrics are served on an HTTPS endpoint guarded by controller-runtime TokenReview/SubjectAccessReview authorization. The Konflux build opts into `strictfipsruntime`, while application TLS defaults and cipher selection remain Go-managed unless environment configuration supplies a profile; the source does not establish a fixed minimum TLS version.
