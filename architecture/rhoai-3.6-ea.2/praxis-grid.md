## Purpose

**Short**: Grid is a distributed Kubernetes control plane that discovers inference providers, scores eligible capacity, and publishes routing overlays consumed by Praxis gateways.

**Detailed**: The operator watches cluster-scoped `GridNetwork`, `GridSite`, and `InferenceProvider` resources. It combines local Kubernetes state with SWIM membership and CRDT-replicated provider state, applies provider-level scoring, and writes versioned ConfigMaps containing routing candidates, gateway metadata, trust material references, and credential references.

Grid is not on the HTTP inference request path: Praxis gateways read the local overlay and perform request translation, provider selection, gateway-to-gateway mTLS, credential injection, and backend proxying. The repository also contains reusable Rust crates for certificates, CRDT state, scoring, SWIM, overlay synchronization, mock provider APIs, development-cluster orchestration, and the operator binary.

## Architectural Analysis

Grid separates a distributed control plane from the Praxis data plane. The operator fans out four Kubernetes reconciliation loops and a metrics server, while an optional SWIM runtime exchanges membership and provider state between sites. `GridNetwork` reconciliation renders a local routing overlay and related consumer configuration into ConfigMaps; `overlay-sync` can watch a named ConfigMap, validate its scope and content-addressed envelope, and atomically publish it to a shared file consumed by Praxis.

The principal trust boundary is between a provider gateway and its private backend. Grid stores references to gateway and credential material and distributes provider eligibility, but does not terminate client traffic or inject credentials itself. Gateway-to-gateway mTLS and backend authorization are implemented by Praxis. Cluster-scoped CRDs and a service account with cluster-wide CRD permissions make this a cluster-level operator; namespaced Secrets, Services, Events, and ConfigMaps are accessed through explicit references and bindings.

The Rust workspace is locked with `Cargo.lock` and uses immutable operator image references in the raw Deployment. TLS clients use rustls with the `ring` provider, and the source explicitly installs that provider process-wide. This is not evidence of FIPS validation; `ring` is not a FIPS-validated provider and no FIPS build gate was found in the component checkout.
