## Purpose

**Short**: Reconciles the cluster-scoped `MCPLifecycleOperator` resource and deploys the MCP lifecycle operand manifests into the operator namespace.

**Detailed**: The operator is a controller-runtime manager that reads platform configuration and the OpenShift API server TLS profile, renders embedded kustomize manifests, and applies the resulting MCP lifecycle resources using server-side apply. It supports an optional related operand image override and records distribution, release, readiness, and degradation status on the management CR.

The controller watches the singleton `MCPLifecycleOperator` named `default`, the managed operand resources, the platform configuration ConfigMap, and (on OpenShift) the `APIServer` resource. It waits for rendered Deployments to become available and garbage-collects managed resources in the operator namespace when the desired set changes or management state becomes `Removed`.

## Architectural Analysis

This is a singleton, cluster-scoped management controller with a namespaced operand footprint. Its cache deliberately limits ordinary objects to `SYSTEM_NAMESPACE` and uses a managed-label selector for cluster-scoped Roles, RoleBindings, and CRDs, reducing unrelated cluster object caching. Reconciliation is idempotent: it renders embedded manifests, applies them with a field owner, removes stale labeled resources in the operand namespace, and waits for all rendered Deployments to become available.

The controller supports both OpenShift and non-OpenShift execution by attempting to read the OpenShift `APIServer` TLS profile and falling back to hardened Intermediate defaults. The principal security concern visible in the checked-out deployment is the default Prometheus `ServiceMonitor` setting `insecureSkipVerify: true`; the repository includes a certificate patch path intended to replace that behavior with a referenced metrics certificate.

The broad cluster RBAC is functionally required for a platform operator that creates CRDs, cluster RBAC, and namespaced operands, but it makes the management ServiceAccount a high-value identity. Namespace and managed-label predicates reduce reconciliation scope; they do not replace API-server authorization or prevent other authorized actors from changing managed objects.
