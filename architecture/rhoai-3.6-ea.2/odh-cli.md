## Purpose

**Short**: odh-cli is a Cobra-based kubectl-style CLI for inspecting, validating, diagnosing, backing up, and migrating RHOAI deployments through Kubernetes APIs.

**Detailed**: The binary is invoked as `kubectl-odh` or `rhai-cli` and uses Kubernetes client-go configuration flags and kubeconfig credentials to operate against an RHOAI cluster. Its command groups cover API discovery, component inspection and mutation, dependency checks, diagnostics, events, logs, linting, status, migrations, backups, and version/completion utilities.

The CLI builds a unified client containing dynamic, discovery, metadata, typed Kubernetes, API extensions, controller-runtime, and OLM clients. Most operations are command-line initiated and do not require a long-running workload. The `mcp serve` command additionally exposes the CLI tools through MCP over stdio by default or an optional loopback SSE HTTP server.

## Architectural Analysis

odh-cli is an operational control-plane client rather than a Kubernetes operator or continuously running service. It translates user commands into Kubernetes discovery, read, mutation, watch, and authorization requests, with namespace-aware helpers used by migration, backup, lint, and status workflows. The application deliberately centralizes REST configuration and client construction, including elevated client-side throttling for parallel operations.

The primary security boundary is the target cluster's kube-apiserver: standard client-go credential sources supply bearer tokens, client certificates, or OIDC-backed credentials, while selected privileged workflows perform `SelfSubjectAccessReview` checks before proceeding. The CLI also has direct outbound HTTPS behavior: it can refresh dependency manifests from a pinned `odh-gitops` commit and can call discovered TrustyAI routes. The latter path sets TLS 1.2 as a minimum but explicitly skips certificate verification for self-signed in-cluster routes, which is a material transport-security risk.

The Konflux build is FIPS-oriented (`CGO_ENABLED=1`, `GOEXPERIMENT=strictfipsruntime`, and strictfipsruntime build tags) and uses digest-pinned UBI/OpenShift images. The ordinary Makefile defaults are less strict (`CGO_ENABLED=0`), so the resulting posture depends on the build recipe used. Go and RPM lock material is present, but the non-Konflux Dockerfile downloads latest external CLI artifacts at build time and the Konflux Dockerfile uses `go mod download` without an explicit Hermeto/cachi2 prefetch step.
