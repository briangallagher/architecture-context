## Purpose

**Short**: MLServer is a pluggable Python inference server that exposes KServe v2-compatible REST and gRPC APIs for loading and serving multiple machine-learning model runtimes.

**Detailed**: The service starts an ASGI/REST server, an asynchronous gRPC server, and an optional Prometheus metrics server. It discovers models through a configurable model repository, maintains a multi-model registry, loads models at startup by default, and routes inference requests to runtime adapters. The image-baked trusted-runtimes artifact restricts production model implementation imports to runtimes selected during image construction.

The repository packages adapters for Alibi Detect, Alibi Explain, CatBoost, Hugging Face, LightGBM, MLflow, Spark MLlib, ONNX, scikit-learn, and XGBoost. CPU and NVIDIA CUDA Konflux images use AIPCC base images; the CUDA image selects the ONNX CUDA execution provider and the CPU image enables a broader default runtime set.

## Architectural Analysis

MLServer is a single process with several coordinated protocol surfaces rather than a Kubernetes controller. `mlserver start $MLSERVER_MODELS_DIR` initializes the model repository, registry, data plane, REST server, gRPC server, and—when configured—metrics and Kafka workers. Model lifecycle operations are centralized in the registry and are shared by REST and gRPC handlers, allowing inference, readiness, metadata, and repository operations to remain protocol-specific adapters over common model state.

The release images deliberately turn runtime selection into a supply-chain control. During image build, `TRUSTED_RUNTIMES` is validated and written to `/etc/mlserver/trusted-runtimes.json`; production startup rejects model implementations outside that allowlist. The image runs as UID 1000 and makes `/opt/mlserver` compatible with random OpenShift UIDs. The platform supplies deployment and authentication context: the checkout contains no Kubernetes manifests, Services, Routes, RBAC, or CRDs, while analyzer evidence associates exposed gRPC methods with a KServe `kube-rbac-proxy` sidecar.

The main security caveats are transport and FIPS configuration gaps in the application itself. The gRPC server calls `add_insecure_port`, REST and metrics use plain Uvicorn HTTP, and no server-side TLS configuration or minimum TLS version is defined in the source. Client-side inference and tracing have opt-in insecure modes. These settings can be acceptable when the KServe/RHOAI data plane terminates and authenticates traffic, but the boundary must remain explicit for deployments that expose MLServer directly.
