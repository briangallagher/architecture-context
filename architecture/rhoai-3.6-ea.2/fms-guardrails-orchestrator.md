## Purpose

**Short**: Orchestrates text generation and content-safety detector services behind a unified HTTP API.

**Detailed**: FMS Guardrails Orchestrator is a Rust middleware service that accepts text, completion, chat, and streaming requests, invokes configured detector and chunker services, and optionally coordinates generation through TGIS, caikit-NLP, or OpenAI-compatible backends. It applies detector thresholds and combines detection with generation so unsafe input or output can be identified and filtered.

The binary separates its operational surfaces into a guardrails API on port 8033 and a health/info API on port 8034. Downstream services are configured through YAML and may use HTTP or gRPC, named TLS configurations, client certificates, API tokens, retries, timeouts, and load-balanced gRPC channels. OpenTelemetry traces and metrics are supported through OTLP exporters.

## Architectural Analysis

The component is a stateless orchestration/data-plane service whose primary architectural value is protocol translation and sequencing: one client request can fan out to chunkers, detectors, and a generation backend, while streaming handlers preserve incremental responses and detection results. Runtime configuration selects detector types, providers, concurrency, timeouts, retries, path prefixes, and telemetry without requiring a Kubernetes API surface.

The two-listener design keeps liveness and service metadata separate from the guardrails API, but the health listener is unauthenticated and unencrypted, so it should remain reachable only on an internal network. Application authorization is intentionally thin: request headers can be filtered and rewritten, but the service does not validate end-user identity or enforce tenant policy. Those controls must be supplied by the platform ingress/service mesh and by downstream services.

The main security risk is configuration-dependent TLS behavior. Configured rustls trust validation is available, but `insecure` explicitly installs a verifier that accepts any certificate, and the client path used when no TLS configuration is supplied also installs that verifier. Release builds use a UBI minimal PQC base and locked Cargo/RPM dependencies, but no repository evidence establishes dynamic linking, check-payload success, or an OLM FIPS declaration.
