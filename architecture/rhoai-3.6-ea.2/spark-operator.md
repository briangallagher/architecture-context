## Purpose

**Short**: Runs and manages Spark applications, scheduled applications, and Spark Connect workloads on Kubernetes.

**Detailed**: The upstream operator watches SparkApplication, ScheduledSparkApplication, and SparkConnect resources and reconciles their driver/executor pods, services, optional UI ingress, status, events, and disruption budgets. It supports namespace filtering, configurable scheduling integrations, metrics, leader election, and resource-quota validation.

The RHOAI module controller watches the cluster-scoped SparkOperator resource, selects the ODH or RHOAI manifest overlay from injected platform configuration, and applies the workload operator resources. This separates platform lifecycle management from the workload reconciliation process. Admission webhooks validate and default Spark resources and mutate Spark-created pods; cert-manager provisions the webhook serving certificate.

## Architectural Analysis

This is a two-layer operator. The module controller provides platform lifecycle, readiness conditions, cleanup, and manifest deployment, while the Kubeflow Spark operator performs the high-frequency, namespace-aware reconciliation of Spark workloads. The controller is configured by default to watch all namespaces, with explicit namespace lists or a namespace selector available for tighter installations (`internal/controller/sparkapplication/controller.go:250-271`).

The primary control flow is Kubernetes API driven: CR events enqueue reconciliation, the operator creates and monitors driver/executor pods and supporting services, and status/events expose progress. Spark Connect adds a gRPC workload path, while Spark UI and driver ingress are represented as Kubernetes Ingress resources rather than RHOAI 3.x Gateway API resources. The platform overlay adds a namespace-scoped NetworkPolicy and monitoring labels, but the policy intentionally permits same-namespace pod traffic.

The release branch uses strict FIPS Go build flags and PQC UBI runtime images, with pinned Go/RPM inputs. Application crypto remains mixed: TLS is delegated to Go/controller-runtime and cert-manager, while MD5 is used only to derive deterministic generated names. The latter is not used as a security primitive but is a notable non-FIPS algorithm signal.
