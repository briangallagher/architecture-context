## Purpose

**Short**: Kubeflow Training Operator reconciles distributed ML training job custom resources into Kubernetes workloads.

**Detailed**: The operator provides the `kubeflow.org/v1` JAXJob, MPIJob, PaddleJob, PyTorchJob, TFJob, and XGBoostJob APIs. Each namespaced job describes replica roles and pod templates for a framework-specific distributed training workload.

The controller manager runs framework reconcilers that create and monitor pods and services, update job status, emit events and metrics, and clean up completed workloads. It can integrate with Volcano or scheduler-plugins for gang scheduling and creates framework-specific network policies and, for PyTorch jobs, HPAs where configured.

In RHOAI, the operator is installed into the `opendatahub` namespace with a `kubeflow-` name prefix. The RHOAI overlay replaces the image with `quay.io/opendatahub/training-operator:v1.9.0-odh-3`, provisions the webhook certificate Secret, exposes Prometheus metrics through a PodMonitor, and preserves the operator's cluster-wide RBAC while allowing an optional namespace restriction through configuration.

## Architectural Analysis

This is a single control-plane Deployment containing one Go controller-runtime manager. Six reconcilers are registered from one process; all supported schemes are enabled by default, while `--enable-scheme` can narrow the set. The manager uses a label-filtered cache for operator-managed Pods, Services, ConfigMaps, Secrets, and Roles/RoleBindings, and can restrict its default namespace through `--namespace`/`KUBEFLOW_NAMESPACE`. With no namespace set, the deployment is cluster-wide.

The operator combines declarative Kubernetes APIs with imperative workload orchestration. A training job remains the source object, while framework controllers derive replica Pods, headless or peer-discovery Services, status, events, and supporting resources. The broad ClusterRole is intentional for cluster-wide operation, but its ability to create Pods, Services, service accounts, Roles, RoleBindings, NetworkPolicies, HPAs, and `pods/exec` makes deployment namespace configuration and user RBAC important isolation controls.

Admission validation is fail-closed for five job kinds and validates names, run policies, and framework-specific replica specifications on CREATE and UPDATE. MPIJob has a registered webhook slot that is currently a no-op. Webhook certificates are generated and rotated in the operator namespace and mounted read-only; the webhook and metrics servers use TLS options derived from the OpenShift APIServer TLS profile or hardened defaults.

| Network traffic | Controllers create per-job NetworkPolicies; PyTorch policy permits job peer traffic and selected namespace traffic | Kubernetes | Policy behavior varies by framework and cluster default posture; no global default-deny policy is declared here. |
| Compute & resources | Per-job replica Pods; optional gang scheduler and HPA integration | Kubernetes scheduler/controller | No ResourceQuota or LimitRange is created by this component. |
| Configuration & secrets | Webhook certificate Secret is scoped to operator namespace; job configuration is in namespaced CRs/ConfigMaps | Kubernetes | Controller ClusterRole can create/read supporting resources across namespaces. |
| API scoping | Namespaced CRDs; optional namespace-filtered cache; framework list operations use job namespace and labels | Kubernetes/controller code | Empty `--namespace` intentionally permits cluster-wide reconciliation. |
